# AGENTS.md — Coding Agent Instructions

## Project Overview

This is the sci5th website: a Next.js 15 (App Router) project in TypeScript with Tailwind CSS. sci5th — exploring the structure of human knowledge, with a focus on science and technology

The site is a deep working prototype intended to scale into a larger application. Keep architecture production-shaped: dynamic routes, config-driven data, shared components.

## Conventions

- **Language:** TypeScript (strict mode). No `any` types unless unavoidable.
- **Styling:** Tailwind CSS utility classes only. No CSS modules or inline `style` objects unless necessary for dynamic positioning.
- **Design tokens:** All colors go through the `ink.*`, `text.*`, `brand.*`, `accent.*`, `feedback.*` tokens defined in `tailwind.config.ts` and mirrored as `:root` CSS variables in `globals.css`. Do not introduce hex literals or raw `slate-*` / `gray-*` classes. See `DESIGN_SYSTEM.md`.
- **Theme:** Dark-only. No light mode, no theme toggle.
- **Fonts:** DM Sans (`font-sans`) for body/shell; JetBrains Mono (`font-mono`) only for the knowledge tree. Loaded via `next/font/google` in `src/app/layout.tsx`.
- **Icons:** `@heroicons/react/24/outline`. When adding a new field to the knowledge tree, extend `FIELD_ICONS` in `src/config/human-knowledge-tree.ts` if an appropriate glyph exists.
- **Components:** React functional components with hooks. No class components.
- **Imports:** Use `@/` path alias for `src/` imports (e.g., `@/components/HumanKnowledgeMap`).
- **Formatting:** Prettier with `prettier-plugin-tailwindcss`. Run `npm run format` before committing.
- **Linting:** ESLint with `eslint-config-next`. Run `npm run lint` to check.

## File Organization

- **Pages** go in `src/app/(main)/` using Next.js App Router conventions.
- **Shared components** go in `src/components/`.
- **Configuration / data** goes in `src/config/` (e.g. `knowledge-gallery.ts`). Knowledge Gallery data is split: `knowledge-gallery.ts` holds per-entry card **metadata** (imported by the client index), `knowledge-gallery-content.ts` holds the per-entry **step prose** (`ENTRY_STEPS`, imported only by the server-rendered detail view so it never ships in the client bundle), and `periodic-elements.ts` holds the 118-element dataset for the interactive Periodic Law hero.
- **Static assets** (logos, images) go in `public/`.
- **Long-form documentation** (the triple-lens review, archived history) goes in `docs/`. Only `README.md`, `AGENTS.md`, and `DESIGN_SYSTEM.md` live at the repo root.

## Key Patterns

- The `(main)` route group provides a shared shell (logo, nav, footer). The logo strip's right-hand accent is `sci5th_Logo_Blue.svg` across all surfaces (`/`, `/human-knowledge`, `/knowledge-gallery`).
- The `HumanKnowledgeMap` component uses a scoped `km-*` CSS block (intentional Tailwind exception). The block lives at the bottom of `src/app/globals.css` and consumes the shared `:root` tokens — do not reintroduce local hex values. Category colors are applied via `cat-formal`, `cat-natural`, `cat-applied`, `cat-social`, `cat-humanities`, `cat-professions` classes at the top level, inherited by descendants.
- The tree supports full ARIA `tree` / `treeitem` semantics with keyboard navigation (↑/↓ move, →/← expand/collapse, Enter/Space toggle, Home/End jump). Preserve these when editing.
- sci5th is the site/brand; future sci5th projects live at sibling top-level routes (e.g., `/[future-project]`).

## Asset References

- **All references to files in `/public/` must go through `assetUrl()`** (`src/config/asset-manifest.ts`) so they pick up a content-hash query suffix. `assetUrl("/Foo.webp")` returns `/Foo.webp?v=<sha256-prefix>` when the file is in the manifest, or the raw path as a fallback. This keeps users from being stuck on a cached v1 after we ship a same-named v2.
- The manifest is **auto-generated** by `scripts/build-asset-manifest.mjs` from every `/public/*.webp`, every Unity build manifest file under `/public/UnityGames/`, and the logo SVGs/favicons. It runs automatically via `npm run prebuild`, manually via `npm run asset-manifest`, and is checked in so the type-checker sees the latest hashes.
- When adding a new file type that needs cache-busting (e.g. `/public/*.mp4`), extend the `GLOBS` array in the script. Routing a single file through `assetUrl()` while leaving it absent from the manifest is harmless — it just won't bust.

## Image Pipeline

- **All Knowledge Gallery thumbnails are 1280×720 WebP, target 60–120 KB.** Drop a `.png` or `.jpg` into `/public/` and let the pre-commit hook handle the conversion via `scripts/optimize-image.mjs`, or run the script directly: `node scripts/optimize-image.mjs public/Foo.png`. Quality auto-tunes between 70 and 80 to hit the target band. Delete the source PNG/JPG by hand once you've verified the WebP.

## Pre-commit Hooks

- Hooks run via **lefthook** (`lefthook.yml`). One-time setup: `npm install` then `npx lefthook install`. Skip a single commit with `git commit --no-verify`. Hooks: auto-optimize new images, regenerate the asset manifest when `/public/` changes, format staged TS/TSX/CSS via Prettier.

## CI

- `.github/workflows/ci.yml` runs on every push to `main` and every PR: `npm ci` → `npm run asset-manifest` → `tsc --noEmit` → `npm run lint` → `npm test` → `npm run build` → `npm run check-bundle-size`. Build failures (including any drift from `output: "export"`) and bundle-budget violations surface in CI before merge.

## Bundle Budget

- Soft cap: **150 KB First Load JS per route.** Enforced in CI by `scripts/check-bundle-size.mjs` after every build. Exempt routes (with a one-line justification) live in the `EXEMPTIONS` object in the script. Current exemptions: `/human-knowledge` at 185 KB (tree `DATA` constant inlined; grows as nodes are added) and `/knowledge-gallery` at 160 KB (card metadata for all entries inlined in the client index). Gallery **step prose** has been moved into `knowledge-gallery-content.ts`, imported only by the server-rendered detail view, so it no longer ships in any client bundle — adding entries now grows only the server side, not `/knowledge-gallery`. The cap is soft: when shipping intentionally heavier content, bump `capKb` (or `CAP_KB`) explicitly with an updated reason rather than letting it slide silently.

## Tests

- Vitest. Pure modules (no React, no DOM) get a `.test.ts` alongside the source — see `src/components/HumanKnowledgeMap.search.test.ts` for the pattern. Run `npm test` (one-shot) or `npm run test:watch`. Tests run in CI between `lint` and `build`.

## Deployment

- **Target: static export.** `next.config.ts` sets `output: "export"`. The build produces a fully static site under `out/` that can be served from any static host (Cloudflare Pages, Netlify, GitHub Pages, S3+CloudFront). Do not introduce server-only features (Route Handlers, Server Actions, middleware that requires a Node runtime, `next/image` with the default loader, ISR, `revalidate`, dynamic `cookies()`/`headers()` reads) — they will break the export. `images.unoptimized = true` is set for the same reason; keep using `unoptimized` on `<Image>`.

## Do

- Keep pages simple — data imported from `@/config/*` at the top, single default export component.
- Use `unoptimized` on `<Image>` for local assets (no Next.js image optimization pipeline).
- Maintain responsive design: mobile-first with Tailwind breakpoints (`md:`, `lg:`).
- Use semantic HTML where appropriate (`<nav>`, `<main>`, `<footer>`).
- Update `README.md` and this `AGENTS.md` when making significant structural changes (per project instructions).

## Standing Rules

- **Use stable tools and libraries only.** Prefer stable, mature, widely-adopted dependencies. Avoid experimental, alpha, or beta packages unless explicitly approved. If only an experimental option exists for a requirement, flag it before adding.
- **Respect copyright and licensing.** When handling images, videos, text, fonts, code snippets, or any third-party asset, verify it is properly licensed or in the public domain. If you spot a potential copyright or legal violation anywhere in the project, surface it with a concrete recommendation to either resolve it (add attribution, replace with a properly licensed alternative) or remove it.
- **Respect `prefers-reduced-motion` in every animation.** Any new animated component must read the user's `(prefers-reduced-motion: reduce)` preference and either skip the animation entirely or replace it with a quiet static equivalent. For JS-driven animation (rAF, requestIdleCallback, setInterval): gate the loop behind a `useEffect` hook that calls `window.matchMedia("(prefers-reduced-motion: reduce)")` (mirror the pattern in `FiveDimensionsHero.tsx` — sync once, subscribe to `change`, snap to the final frame when reduced motion is on). For CSS-driven animation: add a `@media (prefers-reduced-motion: reduce) { … }` block that either sets `animation: none` or swaps the animation for a static box-shadow / outline (mirror the `.km-node[data-highlight="true"]` pattern at the bottom of `globals.css`). Don't ship an animation that has no reduced-motion path.
- **Check the security of everything that enters the project, and also everything that leaves the project.** Vet inbound dependencies, assets, code snippets, data, and user input for known vulnerabilities, malicious content, secrets, or supply-chain risk before they land. Review outbound content, commits, build artifacts, deployments, network calls, and exported data for leaked credentials, PII, internal details, or unsafe destinations before anything ships. Surface concerns with a concrete mitigation.
- **Disclose AI-generated content AND tutorial-derived work.** All Knowledge Gallery prose is AI-drafted and not independently fact-checked; all Knowledge Gallery thumbnails are generated with OpenAI's image model (Images 2.0) unless an entry sets a different `imageSource`. The Unity WebGL builds under `/public/UnityGames/` are NOT fully original — the GOAP Hospital and Behaviour Tree Gallery demos were implemented by following Penny de Byl's Holistic3D courses on Udemy. Those entries are tagged `imageSource: "unity-tutorial"` with `attribution` pointing at the source course. The sci5th logo and site chrome are first-party. The site exposes this through four disclosure surfaces, each with a single responsibility:
  1. **Global footer** (`src/app/(main)/layout.tsx` → `Footer`) — one line about AI-drafted content and a "Learn more" link to `/about`. Does NOT mention images (the per-card credit does that).
  2. **Knowledge Gallery index banner** (`src/components/KnowledgeGallery.tsx`) — `<aside role="note">` above the sub-navbar, reiterates the AI-drafted/not-expert-reviewed caveat. Does NOT mention images or Unity (the per-card credit does that).
  3. **Per-card image credit** (`src/components/KnowledgeGallery.tsx` → overlaid on the thumbnail's bottom-right corner via a soft right-side gradient, gated on `entry.thumbnail`). Caption text comes from `imageCreditFor(entry.imageSource)` — see (4).
  4. **Per-entry hero credit** (`src/components/KnowledgeGalleryEntry.tsx`) — same wording, rendered under the entry's hero. Both surfaces route through `imageCreditFor(source)` in `src/config/knowledge-gallery.ts`, which `switch`es on `entry.imageSource: "openai" | "unity" | "first-party" | "stock"`.
  Plus a dedicated `/about` route (`src/app/(main)/about/page.tsx`) with two sections: "How content is produced" and "What this site is not", followed by a contact line. When adding new entries: set `entry.imageSource` to the correct provenance (default is `"openai"` for AI-generated thumbnails; set `"unity"` for first-party WebGL hero builds; set `"first-party"` for original artwork/diagrams made for the site). If you ever introduce a new provenance, extend the `ImageSource` union AND the `switch` in `imageCreditFor()` — TypeScript will tell you about the second one. Keep image attribution near the image, not in the footer or banner — that separation is intentional. **`first-party` images intentionally show NO credit caption** (surfaces (3) and (4) suppress it): there's nothing to disclose and no third party to credit, so absence of a caption means "original work made for this site." `/about` states this so the silence is explicit. Captions still appear for `openai`, `unity`, `unity-tutorial`, and `stock`.
